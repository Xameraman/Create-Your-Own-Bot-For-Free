A Hugging Face Space is a free server that runs your bot 24/7. Think of it as free cloud hosting for Python apps.

Creating the Space

  • 1
    Go to huggingface.co/new-space while logged in
  • 2
    Fill in the form: Space name: your-name-assistant / SDK: Docker / Visibility: Public

04

Write the Backend (app.py)

This is the core of the bot. Copy this complete starting template into your app.py file on Hugging Face. Then customize the BOT_BASE prompt section with information about your own topic.

app.py — starter template
import logging, os, httpx, time
from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel
from groq import Groq
from cerebras.cloud.sdk import Cerebras

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("bot")

app = FastAPI()
app.add_middleware(CORSMiddleware, allow_origins=["*"],
                   allow_methods=["*"], allow_headers=["*"])

# ── Load API keys from HF Secrets ──
groq_key     = os.environ.get("GROQ_API_KEY")
cerebras_key = os.environ.get("CEREBRAS_API_KEY")

groq_client     = Groq(api_key=groq_key)
cerebras_client = Cerebras(api_key=cerebras_key) if cerebras_key else None

# ── Models to try in order ──
MODELS = [
    ("groq",     "llama-3.1-8b-instant"),   # fast
    ("groq",     "llama-3.3-70b-versatile"), # smart
    ("cerebras", "llama3.1-8b"),             # backup
    ("groq",     "gemma-7b-it"),             # last resort
]

# ── GitHub knowledge files ──
GITHUB_BASE = "https://raw.githubusercontent.com/YOUR_USERNAME/YOUR_REPO/main"

# ── Your bot's personality and topic ──
# CHANGE THIS to describe your own website/community
BOT_BASE = """
You are [YOUR BOT NAME] — the official AI support bot for [YOUR WEBSITE].

[YOUR WEBSITE] is about: [DESCRIBE WHAT YOUR SITE IS ABOUT]

You ONLY answer questions about [YOUR TOPIC].
Be friendly, clear, and helpful.
If you don't know something, say so honestly.
"""

KNOWLEDGE_CACHE_TTL = 600  # cache files 10 minutes
knowledge_cache = {}

async def fetch_knowledge(source: str) -> str:
    now = time.time()
    if source in knowledge_cache:
        if now - knowledge_cache[source]["timestamp"] < KNOWLEDGE_CACHE_TTL:
            return knowledge_cache[source]["content"]
    url = f"{GITHUB_BASE}/{source}.txt"
    try:
        async with httpx.AsyncClient(timeout=10.0) as c:
            r = await c.get(url)
            if r.status_code == 200:
                knowledge_cache[source] = {"content": r.text[:4000], "timestamp": now}
                return r.text[:4000]
    except:
        pass
    return ""

class ChatRequest(BaseModel):
    message: str
    history: list = []
    source: str = "general"

@app.post("/chat")
async def chat(req: ChatRequest, request: Request):
    # Basic length check
    if len(req.message) > 600:
        return {"ok": False, "response": "Message too long. Keep it under 600 characters."}
    if not req.message.strip():
        return {"ok": False, "response": "Please type a message first."}

    # Load knowledge for this page
    knowledge = await fetch_knowledge(req.source)

    system_prompt = BOT_BASE
    if knowledge:
        system_prompt += f"\n\nKNOWLEDGE BASE:\n{knowledge}"
    system_prompt += "\n\nBe concise and helpful."

    messages = [{"role": "system", "content": system_prompt}]
    for msg in req.history[-10:]:
        role = "user" if msg["role"] == "user" else "assistant"
        messages.append({"role": role, "content": msg["content"]})
    messages.append({"role": "user", "content": req.message})

    # Try each model until one works
    for provider, model in MODELS:
        try:
            if provider == "groq":
                resp = groq_client.chat.completions.create(
                    model=model, messages=messages,
                    temperature=0.5, max_tokens=1024, timeout=15)
                reply = resp.choices[0].message.content
            elif provider == "cerebras" and cerebras_client:
                resp = cerebras_client.chat.completions.create(
                    model=model, messages=messages,
                    temperature=0.5, max_tokens=1024)
                reply = resp.choices[0].message.content
            else:
                continue
            return {"ok": True, "response": reply}
        except Exception as e:
            if any(x in str(e).lower() for x in ["429","decommissioned","not found"]):
                continue
            raise

    return {"ok": False, "response": "I'm at capacity right now. Please try again soon."}

@app.get("/")
def root():
    return {"status": "Bot is running", "version": "1.0"}

@app.get("/health")
def health():
    return {"ok": True}
🔧
The only things you must change are:
1. YOUR_USERNAME/YOUR_REPO → your GitHub repo path
2. The BOT_BASE text → describe your own website and topic
05

Create Your Knowledge Files

Knowledge files are plain .txt files stored in a GitHub repo. The bot downloads and reads these files before answering questions so it gives accurate answers about your specific topic.

Create your GitHub repo

  • 1
    Go to github.com/new and create a new public repository. Name it something like my-bot-knowledge
  • 2
    Create your first file — click Add file → Create new file → name it general.txt
  • 3
    Write your content in plain text — no markdown, no HTML, just clear sentences about your topic
  • 4
    Click Commit changes — the file is now live and your bot can read it

What to write in your knowledge files

general.txt — example structure
WHAT IS [YOUR SITE]
[Your site name] is a [describe what it is].
It was created by [your name] for [your audience].
[One more sentence about the main purpose].

HOW TO [MAIN ACTION ON YOUR SITE]
1. [First step]
2. [Second step]
3. [Third step]

COMMON QUESTIONS
QUESTION: [Common thing people ask]
ANSWER: [Clear answer in 1-2 sentences]

QUESTION: [Another common question]
ANSWER: [Clear answer]

RULES AND GUIDELINES
- [Important rule 1]
- [Important rule 2]
- [Important rule 3]

CONTACT AND LINKS
For more help: [your discord / email / contact]
Website: [your website URL]
💡
One file per topic works best. For example: general.txt for overall info, getting-started.txt for beginners, faq.txt for common questions. Each page on your site can load a different file.

Step 3 — Add JavaScript after the HTML

Paste after the HTML above, still before </body>
<script>
(function(){
  // ← CHANGE THESE TWO LINES:
  const API_URL = 'https://YOUR-USERNAME-YOUR-SPACE-NAME.hf.space/chat';
  const SOURCE  = 'general'; // knowledge file to load (without .txt)

  let history=[], isOpen=false, isLoading=false;
  const btn=document.getElementById('bot-btn');
  const panel=document.getElementById('bot-panel');
  const msgs=document.getElementById('bot-msgs');
  const input=document.getElementById('bot-input');
  const send=document.getElementById('bot-send');

  btn.addEventListener('click',()=>{
    isOpen=!isOpen;
    panel.classList.toggle('open',isOpen);
    btn.textContent=isOpen?'✕':'🤖';
    if(isOpen)input.focus();
  });
  input.addEventListener('input',()=>{
    input.style.height='auto';
    input.style.height=Math.min(input.scrollHeight,80)+'px';
  });
  input.addEventListener('keydown',(e)=>{
    if(e.key==='Enter'&&!e.shiftKey){e.preventDefault();sendMsg();}
  });
  send.addEventListener('click',sendMsg);

  async function sendMsg(){
    const text=input.value.trim();
    if(!text||isLoading)return;
    addMsg('user',text);
    history.push({role:'user',content:text});
    input.value='';input.style.height='auto';
    const typing=addTyping();
    isLoading=true;input.disabled=true;send.disabled=true;
    try{
      const res=await fetch(API_URL,{
        method:'POST',
        headers:{'Content-Type':'application/json'},
        body:JSON.stringify({message:text,history:history.slice(0,-1),source:SOURCE})
      });
      const data=await res.json();
      const reply=data.response||'Sorry, something went wrong. Please try again.';
      history.push({role:'assistant',content:reply});
      typing.remove();addMsg('bot',reply);
    }catch(e){
      typing.remove();
      addMsg('bot','⚠️ Could not connect. Please try again in a moment.');
    }finally{
      isLoading=false;input.disabled=false;send.disabled=false;input.focus();
    }
  }

  function addMsg(role,text){
    const d=document.createElement('div');
    d.className='bot-msg '+role;
    d.innerHTML=text
      .replace(/&/g,'&').replace(//g,'>')
      .replace(/\*\*(.*?)\*\*/g,'$1')
      .replace(/\n/g,'
');
    msgs.appendChild(d);
    msgs.scrollTop=msgs.scrollHeight;
    return d;
  }
  function addTyping(){
    const d=document.createElement('div');
    d.className='bot-typing';
    d.innerHTML='
';
    msgs.appendChild(d);msgs.scrollTop=msgs.scrollHeight;
    return d;
  }
})();
</script>

Test Everything

Before sharing your bot with anyone, run through these tests to confirm everything is working.

  • 1
    Test the backend is running — open your HF Space URL in browser (without /chat). You should see: {"status": "Bot is running"}
  • 2
    Test the health endpoint — open your HF Space URL + /health. You should see: {"ok": true}
  • 3
    Test the widget — open your website, click the bot button, type "hello" and press Enter. You should get a greeting response within a few seconds
  • 4
    Test knowledge loading — ask something specific from your knowledge file. If the bot answers correctly, the file is loading properly
  • 5
    Check Hugging Face logs — go to your Space → Logs tab. You should see messages like "✅ GROQ_API_KEY loaded" and "✅ Race winner" when messages are sent

Common problems and fixes

🔴
Bot button shows but no reply appears
Check your HF Space logs. Look for error messages. Most common cause: API key not saved correctly in Secrets.
🔴
500 Internal Server Error in logs
Usually means a Python syntax error in app.py or a missing import. Check the full error message in the logs.
🔴
Knowledge file returns 404
Your GITHUB_BASE URL is wrong. Make sure your GitHub repo is public and the URL matches exactly including username and repo name.
✅
429 Too Many Requests in logs
This is normal and fine. It means one model hit its rate limit and the bot automatically tried the next one. The user still gets a response.

Maintain and Grow

Once your bot is live, keeping it good is simple. Here is what to do over time.

Adding or updating knowledge

Go to your GitHub knowledge repo, click the .txt file, click the pencil icon, make your changes, click Commit. The bot picks up changes automatically within 10 minutes — no restarts needed.

Adding a new page with different knowledge

  1. 1
    Create a new .txt file in your GitHub repo — e.g. products.txt
  2. 2
    Add the widget to your new page with const SOURCE = 'products'
  3. 3
    Done — that page's bot now loads products.txt automatically

If models get decommissioned

Groq occasionally retires old models. If you see model_not_found in your logs, go to console.groq.com/docs/models to find the current model names and update your MODELS list in app.py.
